ML training pipeline, illustrated

From model-ready data through the training loop to what a run leaves behind. K-fold and nested cross-validation sit between the data and the trainer: they decide which rows each training run sees and which hyperparameters it runs with.

Abbreviations used on this page

CVcross-validation — measuring a design by training on some folds and scoring on the fold held out, rotating the held-out fold
K / I / Houter fold / inner fold / hyperparameter set (see the Notation line)
H*the winning hyperparameter set of a round — the one with the best mean inner score
e / bepoch / batch
F1the F1 score — harmonic mean of precision and recall; the metric chosen in Phase V for imbalanced classes
valthe validate rows of a run (inner: 800 rows; judge: 2,000 rows)
lrlearning rate — how far each weight moves per update (0.001 here)
bsbatch size — rows fed through the algorithm per pass (64 here)
dodropout — fraction of neurons switched off per pass during training (0.3 = 30%)
epepochs — how many times the training rows are passed through (30 planned, stopped at 17)
SGDstochastic gradient descent — the basic optimizer rule: move each weight against its gradient, using one batch at a time
AdamWan optimizer in the SGD family that adapts the step size per weight and applies weight decay correctly
∂L/∂wthe gradient: how the loss L changes when weight w changes a little
ŷ / ythe predicted value / the true label
ckptcheckpoint — a saved snapshot of weights, optimizer state and epoch number
RNGrandom number generator state — saved so a resumed run continues with the same randomness
run_id / IDthe unique name of one training run, used to tie its config, checkpoints, metrics and logs together
config.yamlthe run's configuration file — enough to re-run it exactly
SMOTESynthetic Minority Over-sampling Technique — creates new minority-class rows between existing ones; training rows only
MLflowan experiment-tracking tool that stores per-batch and per-epoch metrics, parameters and artefacts
MLmachine learning
A100 / GPUa data-centre graphics processor used to train models; GPU = graphics processing unit
CUDANVIDIA's software layer that lets training code run on a GPU
torchPyTorch, the deep-learning framework used in the example
git 9f3c2a1the exact version (commit) of the pipeline code — part of lineage
Phase II–Vthe CPMAI phases: II Data Understanding · III Data Preparation · IV Model Development · V Model Evaluation
Gate 3the go/no-go at the end of Phase III — data is ready for model development
